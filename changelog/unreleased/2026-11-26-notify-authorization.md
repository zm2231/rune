- `rune-notify`: apps can read notification permission and hear about notifications that never showed. `authorization(f)` calls `f` once with an `Authorization` (`NotDetermined`, `Denied`, `Authorized`, `Provisional`, `Ephemeral`, or `Unavailable` where the app can't post) without blocking: from `UNUserNotificationCenter`'s settings on macOS and iOS, the toast setting on Windows (`Denied` when the person or a policy turned the app's toasts off), and `Authorized` on Linux when a notification server answers. `on_post_error(f)` hears every post the system didn't show, as a `PostError` with the id and a `Failure` (`Denied`, or `System` with the system's description): on macOS and iOS a turned-down or failed permission request (before, `post` returned true and the notification was dropped without a word, the request's error unlogged even in debug builds; debug builds now log it) or a failed add; on Windows a toast posted while toasts are off for the app (`post` returns false) or a failed `Show`; on Linux a failed `Notify` call. `examples/notify-threads` shows the permission and each post error.
