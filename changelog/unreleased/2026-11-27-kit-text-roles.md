- **Text colours by what text means.** `Kit::roles` (`rune_kit::TextRoles`) gives a colour for each `TextRole`: `meta` (timestamps, counts), `link`, `code`, `working` (live work), `added` and `removed` (diffs), `peer` (others' messages), `needs_attention`, `done` and `error`. `TextRoles::from_palette` fills them from a palette's own tokens. `Kit::increased_contrast` moves a role still at its palette colour with that token (so `meta` lifts with faint text) and leaves a role the theme or app set as it is. Kit views take their colours from the roles: markdown links, inline code and diffs; the diff view's added and removed lines; rich text links and code in text fields; invalid field, text area and select text and error messages; the tab strip's attention and failed dots; and the status and diff colours in notes. A theme that sets a role recolours all of them. Inline code keeps its run's colour while `code` is the base text colour; the opencode theme gives code its code accent, so its inline code now draws in that accent. `Kit` gains a `roles` field; a theme that builds a `Kit` literal adds `roles: TextRoles::from_palette(&palette)`. An app that keeps role colours in settings holds a `RoleColor` (a dark and a light colour, and optionally a pair for increased contrast) per role, finds roles by their settings names with `TextRole::named`, and in its `KitTheme` builds `kit.roles.set(role, color.pick(env))`.
