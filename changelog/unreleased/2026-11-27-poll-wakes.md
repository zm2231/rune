- A poll can ask `Tx::wake_at` for the same deadline on every run without piling up wakes: a deadline already pending (to within a microsecond) adds nothing, and `wake_at` now keeps its own deadline instead of drifting with the frame or poll it was scheduled from (a NaN `due` wakes the next frame, a positive-infinite one never wakes). Wakes stay one-shot and keep stacking, so no app's timing changes; a poll that asks `wake_after(d)` on every run still starts a new chain of wakes each time something else makes it poll, so an idle window polls more and more often. Repeat a wake by asking only when arming the timer, or by asking `wake_at` on a fixed schedule; debug builds now say so once when a window holds more than 8 pending wakes the app asked for. `examples/inbox` shows both patterns.
