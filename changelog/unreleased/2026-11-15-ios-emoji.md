- **iOS: emoji draw.** They were blank: Apple Color Emoji on iOS holds each glyph's image in a compressed format of Apple's own (`emjc`), and swash decodes PNG alone. A glyph whose embedded image is in a format swash can't decode is now handed to Core Text to draw into a bitmap, from the font bytes already in memory (no file is opened, and Rune hands the bytes over without copying), and kept in the same colour glyph cache, under the same 16 MB budget, as every other emoji. Rune keeps at most four such faces open, the one used longest ago closed first, and each keeps its font file in memory until then. Other platforms draw as before. `rune::text::ink` still measures an emoji through swash, so on iOS it reports no ink for a text of emoji only. Shown on the iOS simulator (a smiley, a family and a flag in colour at two sizes, each as one glyph; the first emoji drawn in under a frame; the footprint about 6 MB larger, the font not copied); not yet verified on a device.
